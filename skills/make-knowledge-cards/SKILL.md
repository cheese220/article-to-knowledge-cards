# Make Knowledge Cards

把文章转换成少量、可复习、可迁移的知识卡片。目标是帮助用户理解真正重要的信息，而不是覆盖文章中的所有句子。

## 工作流程

1. **确认输入。** 接受用户粘贴的文本，或用户明确给出的本地 `.md`、`.txt` 文件。读取本地文件时必须读取实际内容。若只给了链接、PDF、Anki 导出文件或图形界面操作要求，简短说明暂不支持，不要尝试抓取或转换。
2. **通读并提炼。** 找出中心论点、关键定义、因果关系、判断规则、重要步骤及其边界、核心比较或有代表性的证据。忽略过渡句、重复表述、无关细节和只为装饰论点的例子。
3. **形成单一知识点。** 每张卡片只承载一个可以独立复习的命题、规则或区别。若一句话同时包含两个可分别理解、分别使用的内容，拆成两张卡片；若清单中的多项只是同一个原则的检查步骤，则写在同一张卡中。
4. **去重与收缩。** 合并表达不同但含义重叠的内容，保留信息更完整、条件更准确的一版。做语义去重时问：两张卡是否可以共用一个标题和核心命题而不丢失判断？若能，就合并。不要因为内容来自不同段落就保留重复卡片，也不要为了达到数量而拆分同义表述、琐碎步骤或边缘细节。
5. **写作并核对。** 按下方格式输出；逐张检查事实、范围、条件、因果方向和确定性是否都能在原文中找到依据。

## 选材与数量

- 优先保留读者以后能用于解释、判断、决策或实践的知识；删除只帮助理解当前一句话的铺垫。
- 对教程类文章，卡片应围绕关键决策和操作原则，而不是机械地把每个步骤做成一张卡。
- 对论证类文章，保留主张、理由和重要限定条件；不要为了显得客观而擅自添加反方观点。
- 目标数量为 5–8 张。只有存在足够多彼此独立的重要知识点时才达到 5 张；超过 8 个候选知识点时，选择影响最大的 8 个。
- 原文较短或有效知识点不足时，输出实际能支持的数量，可以是 1–4 张。信息不足以形成连贯知识卡时，说明不足并请用户提供更完整的文本，不要用常识、背景资料或猜测凑数。

## 原文约束

原文是唯一事实依据。

- 不补充原文没有的事实、数据、人物、案例、后果或背景。
- 保留原文中的适用范围、前提、例外、概率、程度和不确定性，不要把“有时”“可能”“在特定条件下”改写成绝对结论。
- 可以压缩、重组和改写原文，但不得改变原意或因果方向。
- 直接陈述知识，不要每张卡片都以“原文指出”“文章认为”开头。只有需要标明证据边界、作者特定主张或引述来源时才使用这类表述。
- 原文有合适例子时，优先改写成简短例子并保留理解例子所需的上下文。
- 原文没有例子时，优先写可依据卡片内容回答的自测题及简短参考。自测不得要求原文之外的信息。不得虚构用户、公司、地点、数字或研究来制造例子。

## 输出格式

使用输入文章的主要语言，除非用户指定其他语言。只输出卡片，不额外复述全文。每张卡片使用以下 Markdown 结构：

```markdown
### 1. 卡片标题

**核心知识**：用一句话写出这张卡最值得记住的命题。

**简明解释**：说明它成立的原因、机制、条件或边界，并与“核心知识”互补。

**例子或自测**：给出忠实于原文的简明例子；原文无例子时，给出基于原文的自测题和简短参考。
```

依次编号，不加“总结”“延伸阅读”等章节。有效知识点不足 5 个时，可以用一句话说明“原文有效知识点有限，以下为 X 张卡片”，但不要为此凑数或反复解释。若用户明确要求保存为文件，可将结果写入其指定的 `.md` 文件；否则直接在回复中给出卡片。
